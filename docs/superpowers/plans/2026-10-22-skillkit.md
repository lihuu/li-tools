**Goal:** Implement a Java skill manager with local/copied skills, metadata-only upstream subscriptions and bounded parallel installation/update, without skills/npm/npx.

**Architecture:** Keep local content under repository skills/, store upstream declarations in skillkit.json, and keep machine installation state beside each agent skills root. Resolve sources once per operation, prepare distinct skills concurrently, and publish managed targets under repository/target process locks with rollback on state write failure.

**Tech Stack:** Java 25, Picocli, cli-common, Jackson streaming JSON, NIO, virtual threads and system Git.

**Spec:** ../specs/2026-10-22-skillkit-repository-design.md

## Global Constraints

- Reuse the task worktree and PR; do not alter main or real user skills.
- Two storage forms only: copied/local content and metadata-only follow subscriptions; no automatic three-way merge.
- No project reflection, var, broad swallowed exceptions, hidden npm dependency, speculative registries or factories.
- Keep stdout results/stderr failures and 0/1/2 exit conventions; inherit shared global options.
- Keep persisted repository declarations portable; preserve unmanaged files and local installation edits.

## Review Focus

- Duplicate local/upstream names and invalid paths must fail without overwriting content.
- Two skills from one source resolve it once, and a failed source cannot be recorded as installed.
- Concurrent processes targeting the same directory must not race publish against state writes.
- Update/remove must refuse changed or unowned targets, and must preserve local original content.
- Dry-run and check must not create directories or alter declarations/installations.
