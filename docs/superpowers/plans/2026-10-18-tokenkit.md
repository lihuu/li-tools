# TokenKit Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `tokenkit`, a modern, zero-runtime-dependency CLI tool in `li-tools` for universal token management, featuring embedded encrypted SQLite storage, transparent machine-bound OS master key providers (macOS Keychain, Windows DPAPI, Linux Secret/file), sub-10ms terminal shell environment injection (`tokenkit env`), and seamless cross-platform backup/export/import.

**Architecture:** Strictly inherits the three-layer architectural pattern from [lihuu/java-cli](https://github.com/lihuu/java-cli): `app` handles entry point wiring and version resolution, `cli` orchestrates Picocli commands and semantic ANSI terminal coloring via `OutputStyle`, and `core` contains decoupled business domain logic (AES-256-GCM crypto engine, platform-specific master key providers, and embedded SQLite storage repository via `sqlite-jdbc`).

**Tech Stack:** Java 25, Picocli 4.7.7, `sqlite-jdbc` 3.49.1.0, JDK 25 `javax.crypto` (AES-256-GCM, PBKDF2), JetBrains Annotations 26.0.2, JUnit Jupiter 5.11.4 / 6.x, GraalVM Native Image.

**Spec:** [tokenkit/SPEC.md](file:///Users/lihu/git/li-tools/.worktrees/tokenkit/tokenkit/SPEC.md) & [docs/superpowers/specs/2026-10-17-tokenkit-design.md](file:///Users/lihu/git/li-tools/.worktrees/tokenkit/docs/superpowers/specs/2026-10-17-tokenkit-design.md)

## Global Constraints

- Java 25 compiler release (`<maven.compiler.release>25</maven.compiler.release>`), Maven multi-module structure under `li-tools`.
- Do not use `var`, including in test code; declare all local types explicitly.
- Pure constructor injection only; zero DI frameworks, zero reflection-based classpath scanning, zero dynamic class loading.
- Public reference parameters and return types must be annotated with `@NotNull` / `@Nullable` from `org.jetbrains:annotations`.
- SQLite storage is 100% embedded (`org.xerial:sqlite-jdbc`); user host requires zero external database installation.
- Default profile is always `'default'`; omitting `--profile` silently routes to `'default'`.
- Standard exit codes: 0 = success, 1 = operational/security failure, 2 = usage error.
- TDD discipline: failing test first, verify failure, implement minimal solution, verify pass, commit.

## Review Focus

- Corrupted or tampered SQLite ciphertext payload must throw `AEADBadTagException` and exit cleanly with code 1, never returning garbage or crashing with unhandled stack trace.
- When `TOKENKIT_MASTER_KEY` environment variable is supplied, it must take unconditional precedence over OS Keychain/DPAPI across all platforms.
- Special characters, newlines, and single/double quotes in token values must be safely escaped in `tokenkit env` outputs for Zsh, Bash, and PowerShell without command injection vulnerabilities.
- `tokenkit import` without flags must default to skipping existing conflicting tokens (`--skip`), outputting yellow warning markers and listing skipped names, while `--overwrite` replaces them.
- If system console is non-interactive or `NO_COLOR` / `--no-color` is set, `OutputStyle` must emit plain text devoid of ANSI escape codes.
