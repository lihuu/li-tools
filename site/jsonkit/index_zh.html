JSON 好用，
查询也顺手。

一条命令格式化文件、在终端高亮，并精确取出需要的值。不依赖 jq，没有子命令，也不用第二个工具。

$ jsonkit response.json
$ jsonkit response.json -p user.name
$ curl -s "$API" | jsonkit -p 'items[*].id'

一个手势，回答两个问题

“让我看看这份 JSON”

两空格缩进格式化，保持成员顺序与数字字面量；只有 stdout 是终端时才为键、字符串、数字和字面量着色。

$ jsonkit package.json
{
  "name": "example",
  "version": "1.0.0"
}

“把这个值给我”

加 -p 使用标准 JSONPath。字段/下标路径输出单个值；通配符、切片、递归和过滤输出数组。

$ jsonkit -p "items[?@.status == 'failed'].id" response.json
[
  1,
  3
]

简写覆盖最常见的场景

你写的路径交给引擎的路径
user.name$.user.name
.user.name$.user.name
[0].id$[0].id
['a.b']$['a.b']
items[?@.status == 'failed'].id$.items[?@.status == 'failed'].id

补根节点之后完全遵循 RFC 9535：字段名、下标、通配符、切片、选择器列表、递归后代、条件过滤和标准函数。

Agent 可以依赖的输出契约

单值

根、字段名和下标路径输出选中的 JSON 值；路径缺失返回 1。

数组结果

通配符、切片、选择器列表、递归和过滤路径始终输出数组；无匹配输出 [] 并返回 0。

默认无颜色

重定向、--no-color 和 NO_COLOR 都输出纯 UTF-8 JSON；是否着色只取决于 stdout。

退出码含义
0成功、帮助、版本，或多值查询无匹配时输出 []
1读取失败、JSON 不合法、查询输入含重复键、单值路径无匹配或资源上限
2CLI 用法错误或 JSONPath 表达式无效

格式化精确保留数字字面量，接受 UTF-8 BOM，拒绝空输入、截断和尾部多余内容。查询输入含重复对象键时直接失败，不会悄悄选中其中一个。

包管理器

brew install lihuu/tap/jsonkit

正式命令是 jsonkit。更短的 jk 是有意的个人 Shell 别名，安装器不会创建它。

常见问题

为什么不直接用 jq？

如果已经装了 jq，它非常优秀。jsonkit 解决的是：格式化与取值合并为一条零依赖原生命令，三平台行为一致，并有明确的自动化输出契约。

能读 stdin 吗？

能。无文件参数时，stdin 是管道或重定向就读取；stdin 是终端则显示帮助而不是等待。用 - 可以显式从终端读到 EOF。

会改写大整数吗？

不会。数字按原始字面量写出，30 位整数或带尾零的高精度小数在格式化和查询输出中都保持不变。

查询有什么资源上限？

最多访问 10,000,000 个节点、返回 1,000,000 个结果节点、嵌套 1,000 层。超过上限返回 1 并给出诊断，而不是耗尽进程。
