HTTPS 流量，
可读。

本地抓包代理：自动生成 CA、按 host 签发证书，每条流量输出一行 JSON。 一个 native 单文件，macOS、Linux、Windows 行为一致。

$ mitmkit ca
$ mitmkit run --jsonl
$ curl -x http://127.0.0.1:8080 --cacert ~/.mitmkit/ca/ca.crt https://example.com/

三步，一个 CA

1. 生成 CA

一个 ECDSA P-256 根 CA 位于 ~/.mitmkit/ca/，跨运行复用，除非 --force 不重建。

$ mitmkit ca --json
{"caCert":"~/.mitmkit/ca/ca.crt",...}

2. 装一次信任

mitmkit run --install-trust 把 CA 写进系统信任库（登录钥匙串、CurrentUser Root 或 anchors）。也可用 certkit trust install。

$ mitmkit run --install-trust

3. 捕获流量

启动代理后，每个请求在 stdout 输出一行 JSON——可直接喂给 jq、脚本和 agent。

$ mitmkit run --jsonl
{"id":1,"method":"GET","status":200,...}

记录哪些字段

字段含义
id, ts递增 flow id 与 ISO-8601 时间戳
method, url请求方法与完整 URL
status响应状态码，失败时为 null
durationMs往返耗时（毫秒）
reqBytes, resBytes请求体与响应体大小
reqHeaders, resHeaders请求头与响应头，仅 --record-headers 时输出
reqBody, resBody请求体与响应体，仅 --record-body 时输出
error失败信息，仅失败时输出

字段在 macOS、Linux、Windows 上完全一致。错误记为 status 为 null 的 flow，输出始终可机器解析。

改写流量

抓包工具的意义在于改，而不只是看。简单 flag 都是整体替换——同名头有则替换、无则追加，Cookie 合并进现有 Cookie 头。

简单 flag

mitmkit run --url https://staging.example.com
mitmkit run --header 'X-Debug:1'
mitmkit run --cookie 'session=abc'
mitmkit run --body '{"user":"admin"}'
mitmkit run --response-header 'X-Mitm:yes'
mitmkit run --response-body '{"ok":true}'

高级规则

mitmkit run --rewrite 'url:/v1->/v2'
mitmkit run --rewrite 'method:POST;reqHeader:X-Debug:1'
mitmkit run --rewrite 'resBody:{"ok":true}'

用 --match SUBSTR 把简单 flag 限定到匹配的 URL。

agent 可信的输出约定

脚本用 JSONL

--jsonl 每行一个 JSON 对象。人类可读行是终端默认；重定向输出始终可解析。

仅显式代理

常规代理模式：遵守 HTTP 代理设置的客户端会被拦截。首期不含 TUN/透明模式。

上游证书校验

默认校验上游证书。--insecure 跳过校验，用于自签上游场景。

退出码含义
0成功、帮助、版本，或 Ctrl+C 正常退出
1CA 生成失败、端口占用，或交换错误 flow
2CLI 用法错误

安装单个命令

Shell 安装器

curl -fsSL https://tools.lihu.me/install.sh | bash -s mitmkit
mitmkit --version

包管理器

brew install lihuu/tap/mitmkit
scoop install mitmkit

正式命令是 mitmkit。更短的别名由用户自行设置，安装器不创建。

FAQ

为什么不直接用 mitmproxy？

mitmproxy 成熟且强大。mitmkit 面向更窄的需求：native 单文件、三平台命令面一致、为脚本和 agent 内置 JSONL 输出。

CA 存在哪里？

默认 ~/.mitmkit/ca/，可用 MITMKIT_CA_DIR 覆盖。与 certkit 的 CA 相互独立，卸载一个不影响另一个。

支持 HTTP/2 或 WebSocket 吗？

首期不支持。伪造证书只协商 http/1.1，请求 h2 的客户端回落到 http/1.1。拦截连接上的 WebSocket 升级不受支持。

局域网其他设备能用吗？

可以。运行 mitmkit run --host 0.0.0.0，把设备的代理指向你的机器，并先在设备上安装 CA。
