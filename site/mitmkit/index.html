HTTPS traffic,
readable.

A local interception proxy that generates its own CA, signs per-host certificates, and prints every flow as JSONL. One native binary, identical on macOS, Linux and Windows.

$ mitmkit ca
$ mitmkit run --jsonl
$ curl -x http://127.0.0.1:8080 --cacert ~/.mitmkit/ca/ca.crt https://example.com/

Three steps, one CA

1. Generate the CA

One ECDSA P-256 root CA lives in ~/.mitmkit/ca/. It is reused across runs and never regenerated without --force.

$ mitmkit ca --json
{"caCert":"~/.mitmkit/ca/ca.crt",...}

2. Trust it once

mitmkit run --install-trust writes the CA into the OS trust store (login keychain, CurrentUser Root or anchors). Or use certkit trust install.

$ mitmkit run --install-trust

3. Capture flows

Start the proxy and every request becomes one JSON line on stdout — ready for jq, scripts and agents.

$ mitmkit run --jsonl
{"id":1,"method":"GET","status":200,...}

What gets recorded

FieldMeaning
id, tsSequential flow id and ISO-8601 timestamp
method, urlRequest method and full URL
statusResponse status, or null when the exchange failed
durationMsRound-trip time in milliseconds
reqBytes, resBytesRequest and response body sizes
reqHeaders, resHeadersHeaders, only with --record-headers
reqBody, resBodyBodies, only with --record-body
errorFailure message, only when the flow failed

Fields are stable across macOS, Linux and Windows. Errors are recorded as flows with a null status, so the output stays machine-parseable.

Rewrite traffic

The point of an interception proxy is to change traffic, not just watch it. The simple flags replace whole values — headers are appended when absent and replaced when present, cookies merge into the existing Cookie header.

Simple flags

mitmkit run --url https://staging.example.com
mitmkit run --header 'X-Debug:1'
mitmkit run --cookie 'session=abc'
mitmkit run --body '{"user":"admin"}'
mitmkit run --response-header 'X-Mitm:yes'
mitmkit run --response-body '{"ok":true}'

Advanced rules

mitmkit run --rewrite 'url:/v1->/v2'
mitmkit run --rewrite 'method:POST;reqHeader:X-Debug:1'
mitmkit run --rewrite 'resBody:{"ok":true}'

Use --match SUBSTR to scope the simple flags to matching URLs.

An output contract agents can trust

JSONL for scripts

--jsonl prints one JSON object per line. Human-readable lines are the terminal default; redirected output stays parseable.

Explicit proxy only

Regular proxy mode: clients that honor an HTTP proxy setting are intercepted. TUN/transparent mode is out of scope for the first release.

Upstream verification

Upstream certificates are verified by default. --insecure skips verification for self-signed upstreams.

Install the single command

Shell installer

curl -fsSL https://tools.lihu.me/install.sh | bash -s mitmkit
mitmkit --version

Package managers

brew install lihuu/tap/mitmkit
scoop install mitmkit

The official command is mitmkit. A shorter alias is intentionally a personal shell choice, not something the installer creates.

FAQ

Why not just use mitmproxy?

mitmproxy is mature and powerful. mitmkit exists for a narrower need: a native single file with an identical command surface on all three platforms and JSONL output built for scripts and agents.

Where is the CA stored?

~/.mitmkit/ca/ by default, overridable with MITMKIT_CA_DIR. It is independent of certkit's CA so uninstalling one does not affect the other.

Does it handle HTTP/2 or WebSocket?

Not in the first release. Forged certificates negotiate http/1.1; clients requesting h2 fall back to http/1.1. WebSocket upgrade over an intercepted connection is not supported.

Can other devices on my network use it?

Yes. Run mitmkit run --host 0.0.0.0 and point the device's proxy at your machine. Install the CA on the device first.
