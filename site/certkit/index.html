❌ The Pain of Raw OpenSSL

  • • Hostile CLI: Having to write temporary openssl.cnf just to inject SAN extensions
  • • Format conversion nightmare: Memorizing complex flag matrices for x509, pkcs12, rsa
  • • Broken Windows experience: No built-in openssl and no straightforward way to inject root trust
  • • Tedious inspection: Pipelining multiple commands just to view expiration dates

✅ The certkit Experience

  • • Convention over configuration: certkit gen localhost auto-detects IP vs DNS
  • • Local CA reuse: Automatically manages root CA in ~/.certkit/ca/ for trusted local development
  • • Single-argument conversion: certkit convert server.crt auto-locates key and outputs PKCS#12
  • • Non-elevated Windows 11 trust: certutil.exe -user injects root CA with zero UAC prompts

Command Matrix

certkit gen [domain/ip]

Smart positional argument deduction, auto-injects IP/DNS SAN extensions, signed by local CA, defaults in-place.

certkit ca init

Initialize a dedicated local Root CA (default 10 years) for your machine, ending self-signed certificate clutter.

certkit check [file | host:port]

High-speed inspection of local .crt/.pem/.p12 files (pure JDK) or remote TLS probe with --json support.

certkit convert <file>

Single-argument bidirectional conversion: PEM automatically grabs matching key for P12; P12 unpacks certificates and keys.

certkit trust [ca | <cert>]

Cross-platform trust injection: macOS Keychain, Linux update-ca-certificates, Windows 11 non-elevated certutil.

certkit raw <args...>

Unconstrained escape hatch: directly forwards arguments to the host OpenSSL binary for specialized administrative workflows.

certkit doctor

Cross-platform diagnostics: checks OpenSSL engine (including Git for Windows path), CA integrity, and OS trust store status.

Frequently Asked Questions

Why does Chrome reject standard self-signed certificates?

Chrome and modern Chromium browsers require the Subject Alternative Name (SAN) extension to be present on all certificates. Legacy certificates specifying only Common Name (CN) are automatically rejected. certkit automatically detects domain and IP arguments and embeds compliant SAN extensions.

Where does certkit store my private keys and Root CA?

Your Root CA is stored securely under ~/.certkit/ca/ with restricted filesystem permissions (mode 0600 on keys). Generated server certificates default to the current working directory.
