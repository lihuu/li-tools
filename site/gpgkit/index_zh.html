⚡ 快速安装 (Quick Install)

brew install lihu/tools/gpgkit

❌ 曾经 GPG 令人抓狂的体验

  • • 记不住长参数：每次查指纹都要搜 --keyid-format=long
  • • 备份无验证：导出了一堆文件，换机器导入发现根本用不了
  • • 繁琐交互：导入后还要手动编辑信任度 trust -> 5 -> save
  • • 无头卡死：在 SSH 或 CI 中经常弹出图形 pinentry 导致流程挂起

✅ gpgkit 的现代救赎

  • • 极简动词：gen, backup, restore, doctor
  • • 强制回环校验：任何一次备份，必须在沙盒当场证明能还原且能验签
  • • 非交互设计：所有外部命令固定静默参数，绝不卡死终端
  • • 零依赖单文件：原生独立二进制，不要求机器安装 JDK

核心命令速查 (Command Matrix)

gpgkit status

巡检本机密钥：指纹、剩余天数、私钥存在性、公钥是否在公钥服务器可见，给出 OK/WARN 结论。

gpgkit gen

一键生成现代签名密钥对（默认 rsa4096 / 2 年有效期），自动提取 git 用户名邮箱，生成后强制提示备份。

gpgkit backup

第一等公民：加密导出私钥并写入元数据，当场在独立沙盒执行回环还原与验签，证明 100% 可用才落盘。

gpgkit restore <backup-file>

在新机器上还原备份，自动恢复 Ultimate 最终信任度，当场生成临时测试签名完成闭环验证。

gpgkit extend [--by 2y]

一键为主密钥和所有子密钥续期，避免密钥过期导致 git commit 签名失效。

gpgkit doctor

全面体检：gpg 引擎、备份存在性与可解密性、口令文件安全性，无参数自检并输出一句话结论。

常见问题 (FAQ)

什么是 gpgkit backup 中的“回环测试 (Loopback Test)”？

在备份执行时，gpgkit 会在内存中建立一个完全隔离的临时沙盒 Keyring，把刚导出的加密归档导入进去，使用生成的口令解密并为测试数据生成离线签名，最后验证签名。只有整个闭环 100% 成功，才会将备份归档写入 ~/.gpgkit/backups/。

gpgkit 是重新实现了一套加密算法吗？

不是。gpgkit 不重复造密码学轮子，底层依然使用系统标准的 gpg 引擎。它的核心价值是命令编排、严格校验与安全保障，把最容易配错、最容易被遗忘的操作固定成确定性的安全逻辑。
