常见问题 (FAQ)

运行 li-tools 需要在电脑上安装 Java / JDK 吗？

不需要。虽然源码基于 Java 25 编写，但最终发布产物经 GraalVM Native Image 提前编译为独立原生机器码二进制（支持 x86_64 与 arm64），无任何 JVM 依赖，启动毫秒级。

certkit 是如何让本地开发网站直接实现全绿锁的？

执行 certkit ca 会在本地初始化根证书授权机构并注入操作系统受信库；之后运行 certkit gen 签发的所有证书均由该本地 CA 签发并自动注入 SAN 扩展，浏览器访问即可获得原生绿锁。

gpgkit 如何确保备份 100% 能还原成功？

gpgkit 在每次执行备份时，都会在独立的临时沙盒 Keyring 中当场还原解密，并用还原出来的私钥完成一次真实的签名与校验闭环。一旦检验未通过，备份当场终止且绝不落盘半成品。

tokenkit 如何保障 API 密钥不发生代码仓库泄漏？

tokenkit 摒弃了在项目内散落明文 .env 文件的传统做法。所有密钥集中密文保存在全局 ~/.tokenkit/tokens.db（AES-256-GCM 加密），通过 eval $(tokenkit env) 在 10ms 内直接注入当前终端进程内存，磁盘零落地，Git 零污染。

skillkit 如何简化多个 AI Coding Agent 的技能管理？

无需手工编写软链脚本或依赖笨重的 Node.js/npm 生态。skillkit 通过 Java 25 虚拟线程高并发，一条命令将个人原创与第三方 Git 仓库自动广播分发至 10+ 主流 AI Coding Agent（Claude Code、Codex、Cursor、Gemini CLI、OpenCode、Antigravity 等），并提供严格的作用域自动提交与远端推送。
